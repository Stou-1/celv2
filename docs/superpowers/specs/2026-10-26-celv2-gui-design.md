# CelV2 GUI アプリ（設計）

日付: 2026-10-26

## 目的

x264guiEx のように、画面で設定を選んで動画を AV2 に変換できる単体の GUI アプリを作る。H.264 / H.265 などの動画ファイルを入れれば、CelV2 で AV2 にできる。後で AviUtl2 の出力プラグインにできる余地を残す。

### 前提（ユーザーとの合意）

- 一番大事にするのは手軽さ。ファイルを入れて、おすすめの設定で変換を始められること。細かい設定は奥に置く。
- 出力の既定は MP4（映像と音声を1つにまとめる）。今の ffmpeg（9.0.2）は AV2 を mp4 / mkv / webm に入れられないので、別セッションで作った av2-tools の `av2_mux`（AV2 の映像だけの MP4 を作る）と GPAC の MP4Box（音声を足す）を使う（下の「MP4 にまとめる」）。道具がないときは「別ファイル（IVF + 音声）」に切り替えて知らせる。詳細設定で「別ファイル」も選べる。
- 他の人にも配る（GitHub などで公開）。
- 作り方: C#、.NET Framework 4.8 の WinForms。Windows 10 / 11 に最初から入っているので追加インストールが要らず、GUI 本体は 1 MB 以下になる。x264guiEx と同じ系統（C++/CLI から WinForms の画面を呼べる）なので、AviUtl2 のプラグインから同じ画面を使い回せる。4.8.1 ではなく 4.8 向けに作る（4.8 向けは 4.8.1 の上でも動き、Windows 10 で 4.8.1 が入っていない PC でも動く）。
- 後で 10 / 12 ビットの HDR に対応するときの工数が減るように、ビット深度と色の情報を最初から設定の一部として扱う（下の「ビット深度と HDR への備え」）。

## 全体像と部品

置き場所は CelV2 リポジトリの `gui/`。

1. `CelV2.Settings`（クラスライブラリ、画面なし）
   - 符号化の設定: 画質（qindex）、タイル、判定の場所（`--device`）、キーフレーム間隔、スレッド数、出力形式（ビット深度、色の情報）。
   - プリセット: 組み込みの「高画質 / 標準 / 小さめ」（qindex 120 / 150 / 180）と、利用者が保存したもの（JSON、`%APPDATA%\celv2gui\presets\`）。
   - 入力の情報（ffprobe の結果: 解像度、フレームレート、可変フレームレートか、インターレースか、ビット深度、色の情報、HDR のメタデータ、音声の有無、フレーム数）。
   - 設定と入力の情報から、ffmpeg（映像の取り出し、音声の取り出し）と celv2enc のコマンドライン引数を組み立てる処理。ffmpeg の画素形式とフィルタの組み立ては、それぞれ1つの関数にまとめる（HDR 対応のときに直す場所を1か所にするため）。
   - 画面と切り離した純粋な処理で、単体テストで確かめる。
2. `CelV2.Runner`（クラスライブラリ、画面なし）
   - ffmpeg（y4m を標準出力へ）と celv2enc（`-i -` で標準入力から）を起動し、プログラムの中でバイト列のままつなぐ（PowerShell 5.1 のパイプ問題は起きない）。
   - 音声の取り出し（ffmpeg、最初の音声トラックだけ）。元の符号のまま取り出す（`-vn -c:a copy`）: AAC → `.m4a`、MP3 → `.mp3`、Opus → `.opus`、AC-3 → `.ac3`、FLAC → `.flac`。それ以外の符号は AAC（192 kbps）に変換して `.m4a` にする。音声がない入力では音声ファイルを作らない。
   - 進み具合の読み取り（celv2enc の `--progress`）、中止（両方のプロセスを止める）、エラーの報告（エラー出力の最後の数行）。
   - 「映像と音声をまとめる段」は差し替えられる部品（インターフェース）にする。実装は「MP4 にまとめる」と「別ファイルのまま」の2つ。
3. `CelV2.Ui`（クラスライブラリ、WinForms の画面）
   - 主画面と、詳細設定のダイアログ。AviUtl2 のプラグインからも呼べるよう、画面は実行ファイルではなくライブラリに置く。
4. `CelV2Gui.exe`（起動用の小さな実行ファイル）。`CelV2.Ui` の主画面を開くだけ。

### celv2enc 側の変更

- `--progress`: 1枚符号化するたびに、標準エラーに `progress frame=N` を1行出す。全体の枚数は GUI が ffprobe で調べる。

### AviUtl2 プラグインにするとき

`CelV2.Settings` と、`CelV2.Ui` の詳細設定ダイアログはそのまま使う。`CelV2.Runner` の「ffmpeg で映像を読む」部分を「AviUtl2 から受け取った映像を celv2enc の標準入力に流す」部分に差し替える。

## MP4 にまとめる

参考: 別に作った MP4 化のスクリプト（変更せず、手順だけ使う）。

1. IVF から OBU の並びに戻す: 先頭のヘッダ（長さはオフセット 6 の u16）と、各フレームの 12 バイトのヘッダ（u32 の大きさ + u64 の pts）を外して中身をつなぐ（`av2_mux` は IVF を受け付けない）。
2. `av2_mux <入力.obu> -o <出力.mp4> --fps <rate>/<scale>`（IVF ヘッダの値。celv2enc は rate = fps、scale = 1）。`--fps` を渡さないと 30 fps 扱いになる。色の情報が分かっていれば `--colr-override cp:tc:mc:fr`（数値）も渡す（`av2_mux` は自分では colr を書かない）。
3. 音声があれば `mp4box -noprog -add <音声> <出力.mp4>`（その場で書き換える）。MP4 に入れる音声は、AAC ならそのまま、それ以外は AAC 192 kbps に変換して取り出す（MP4Box での確認が AAC だけのため）。音声は映像の長さ（フレーム数 ÷ fps）で切る（ffmpeg の `-t`）。
4. 中間の `.obu` と音声ファイルを消す。

道具:

- `av2_mux.exe`: av2-tools（github.com/AOMediaCodec/av2-tools、ffbcb39）を MSVC でビルドし、tkhd の表示サイズの修正（`<別の作業フォルダ>\patches\av2-tools-tkhd.patch`）を当てたもの。BSD-3-Clause-Clear なので配布物に同梱する（`LICENSE` / `PATENTS` と、元のコミットと修正の説明を添える）。
- MP4Box（GPAC、LGPL-2.1）: 同梱しない。ffmpeg と同じ順（設定で指定した場所 → GUI と同じフォルダ → PATH）で探し、見つからなければ入手先を案内する。

既知の制限:

- `av2_mux` v1 は、新しい CVS を始めるキーフレーム（CLK）が2枚以上あると失敗する。celv2enc の `--keyint` では起きなかったが、失敗したら出力を残さず、理由を返す。
- `pasp`（画素の縦横比）は書かれないので、表示サイズ = 映像サイズ。
- ffmpeg / ffprobe は av02 を復号できない（コンテナの値は読める）。

## 画面の流れ

主画面（1画面で完結）:

1. 入力: 大きな「ここに動画をドロップ」の領域と「ファイルを選ぶ」ボタン。複数のファイルを入れたら、上から順に1本ずつ変換する（一覧に状態を表示）。
2. 入力の確認: 入れた時点で ffprobe で調べ、解像度・フレームレート・長さ・音声の有無を一覧に表示する。必要な変換は自動で行い、その旨を一覧に注意として出す。
   - 10 ビット・12 ビットの素材は 8 ビットに変換する。
   - HDR の素材は SDR に変換する（トーンマッピング。下の「ビット深度と HDR への備え」）。
   - 可変フレームレートは固定にする。
   - インターレースは解除する。
3. 画質: プルダウンで「高画質 / 標準 / 小さめ」と、保存したプリセットから選ぶ。既定は「標準」。
4. 詳細設定（ボタンで開くダイアログ）: qindex（スライダー、1〜255）、タイル（自動 / 1 / 2 / 4）、判定（自動 / GPU / CPU）、キーフレーム間隔、スレッド数、「プリセットとして保存」。タイルの「自動」は、幅 1280 以上で2タイル（`--tile-columns 1`）、それ未満で1タイル。
5. 出力先: 既定は入力と同じフォルダに `名前.mp4`（「別ファイル」なら `名前.ivf` と音声（`名前.m4a` など））。フォルダは変えられる。詳細設定に「出力形式: MP4 / 別ファイル」。MP4 に必要な道具がなければ、その旨を一覧に注意として出し、別ファイルで保存する。
6. 実行: 「変換開始」で、1本ごとに進み具合のバー（N / 全枚数）、速さ（fps）、残り時間、判定の場所（GPU / CPU、celv2enc の表示から取る）を出す。「中止」で止める。
7. 終了: 完了を知らせ、「フォルダを開く」を出す。失敗したら理由を出して次のファイルへ進む。

最後に使ったプリセットと出力先は、次に起動したときも同じにする（`%APPDATA%\celv2gui\settings.json`）。

## ffmpeg と配布

ffmpeg（最初の版は同梱しない）:

- ffmpeg と ffprobe を、設定で指定した場所 → GUI と同じフォルダ → PATH の順に探す。見つからなければ、入手先と「ffmpeg.exe を選ぶ」ボタンのある画面を出す。
- 同梱しない理由: 広く使われている ffmpeg のビルドは GPL で、同梱するとソースを提供する義務が生じる。必要になったら LGPL のビルドの同梱を検討する。

配布物（zip、インストーラーなし）:

- `CelV2Gui.exe`、`CelV2.Settings.dll`、`CelV2.Runner.dll`、`CelV2.Ui.dll`、`celv2enc.exe`、`av2_mux.exe`（と av2-tools の `LICENSE` / `PATENTS`、元のコミットと修正の説明）
- VC++ ランタイムの DLL（`vcruntime140.dll`、`msvcp140.dll` など）を同じフォルダに置く（Microsoft が認めている配り方。celv2enc を静的リンクにすると AVM のライブラリも作り直しになるため）。
- ライセンス: CelV2（BSD-3-Clause-Clear）、AVM の `LICENSE` / `PATENTS`、GUI（BSD-3-Clause-Clear）。
- 日本語の説明書（必要なもの: Windows 10 / 11 の 64 ビット。GPU で速く動かすには NVIDIA の Turing 以降と r580 以降のドライバ）。
- コード署名はしない（初回の実行で SmartScreen が警告を出す）。

## ビット深度と HDR への備え

AV2 v1.0 の規格で使えるビット深度は 8 と 10 だけ（`bit_depth_idc` は 1 以下、6章の表 6.3。プロファイルはすべて `Main_*_10`、附属書 A の表 A.1）。12 ビットの素材は、10 ビット対応後も 10 ビットに落として符号化する。HDR10 / HLG はもともと 10 ビットなので、10 ビット対応で HDR の大半をまかなえる。

今回の GUI で行う備え（後で直す場所を少なくする）:

- 設定の「出力形式」に、ビット深度（今は 8 のみ。10 を受け付ける形にしておき、celv2enc が対応するまでは選べないようにする）と色の情報（色域、伝達特性、行列係数、範囲）を持たせる。
- 入力の情報に、ビット深度・画素形式・色の情報・HDR のメタデータ（マスタリングディスプレイ、コンテンツの明るさ）を含める。今は表示と変換の判断に使い、10 ビット対応後はそのまま celv2enc に渡す。
- ffmpeg の画素形式（今は `yuv420p`。将来 `yuv420p10le`）と、ビット深度・HDR の変換フィルタ（今は HDR → SDR のトーンマッピング。将来は 10 ビットのまま通す）は、それぞれ1つの関数で決める。
- HDR → SDR の変換は ffmpeg の `zscale` と `tonemap` フィルタで行う。ffmpeg のビルドにこれらがない場合は、その入力を「HDR の変換に必要な ffmpeg の機能がない」として失敗にする（色が正しくない映像を黙って作らない）。
- celv2enc 側の将来の引数（`--bit-depth 10`、色の情報）は、コマンドライン組み立ての中で「ビット深度が 8 でなければ付ける」形の1か所に置く。今は 8 以外を渡すと「未対応」の例外にする。

CelV2 本体で 10 ビット対応のときに直す場所（2026-10-26 時点）:

| 場所 | 8 ビットの前提 |
|---|---|
| `src/io/y4m.{h,cpp}` | `Frame420` の画素が `uint8_t`。`C420p10` などを「未対応」にしている |
| `src/bitstream/seq_header.cpp` | `bit_depth = AVM_BITS_8` |
| `src/core/quant.cpp`、`src/gpu/kernels_ref.cpp` | 量子化の段階と λ を `AVM_BITS_8` で計算 |
| `src/core/encoder.cpp`（残差の計算） | 原画を `uint8_t` で読む |
| `src/state/codec_state.cpp`（復元のコピー） | AVM の 16 ビットのバッファを `uint8_t` に落としている |
| `src/gpu/intra_common.h`、`src/gpu/kernels.{h,cu}` | GPU の `Plane` が `uint8_t`。縮小・SATD も 8 ビット |
| `src/verify/avm_decode.cpp` | 8 ビットの出力だけを受け付ける |

AVM の内部のバッファはもともと 16 ビットなので、AVM 側の変更は要らない見込み。

## エラー処理

| 状況 | 動き |
|---|---|
| ffmpeg / ffprobe が見つからない | 入手先と「選ぶ」ボタンのある画面を出す |
| 入力が読めない | そのファイルを「失敗」にして理由を出し、次のファイルへ進む |
| 出力先に同名のファイルがある | 上書きせず、`名前 (2).ivf` のように名前をずらす |
| 書き込みに失敗（ディスクが一杯など） | 失敗として理由を出し、作りかけのファイルを消す |
| 中止 | 両方のプロセスを止め、作りかけのファイルを消す |
| HDR の変換に必要な ffmpeg の機能がない | そのファイルを失敗にして理由を出す |
| MP4 に必要な道具（`av2_mux` / MP4Box）がない | 別ファイル（IVF + 音声）で保存し、その旨を一覧に出す |
| `av2_mux` / MP4Box が失敗 | そのファイルを失敗にして理由を出し、作りかけの MP4 と中間ファイルを消す |
| GPU がない | celv2enc が自動で CPU 判定に切り替え、画面に「CPU で判定中」と出す |

## テスト（実装より先に書く）

1. `CelV2.Settings`（自動テスト）: プリセットの保存と読み込みの一致、組み込みプリセットの値（120 / 150 / 180）、コマンドラインの組み立て（タイルの自動規則、`--device`、キーフレーム間隔、スレッド数、空白や日本語を含むパスの引用符、ビット深度 8 以外で「未対応」）、ffmpeg の画素形式とフィルタ（SDR 8 ビット、10 ビット SDR、HDR10、可変フレームレート、インターレース）、出力名のずらし。
2. `CelV2.Runner`（本物の ffmpeg と celv2enc を使う自動テスト）: ffmpeg で作った短い合成映像（2秒、音声付き）を変換して IVF と音声ファイルができること。IVF が同じ設定のコマンドライン（`ffmpeg ... | celv2enc -i -`）とバイト単位で同じこと。進み具合の通知が全枚数ぶん届くこと。中止で2秒以内に両方のプロセスが止まり、作りかけのファイルが消えること。失敗したときに理由が返ること。
3. MP4（`CelV2.Runner`、`av2_mux` / MP4Box / `av2_demux` / `avmdec` を使う）: 合成映像（AAC 付き）で MP4 ができ、ffprobe で av02 と mp4a の2トラック。`av2_demux` で戻した OBU を `avmdec` で復号した結果が、IVF の復号と一致。音声なしの入力では映像だけの MP4。`av2_mux` が失敗したら出力が残らず、理由が返る。MP4Box が見つからなければ別ファイルで保存される。
4. celv2enc の `--progress`（C++ のテスト、`test_cli`）: 1枚ごとの行が全枚数ぶん出ること。
5. 画面（手動の確認表 + スクリーンショット）: ドロップ、プリセットの選択、詳細設定、進み具合、中止、完了、エラー表示、ffmpeg が見つからないときの画面。

## 成功の基準

- 手元の H.264 + AAC の mp4（`eftft_demo_VGA.mp4`）をドロップすると MP4 ができ、av02 と mp4a の2トラックを持つ。中の AV2 は、コマンドラインで同じ設定にして作った IVF と同じ復号結果になる（`av2_demux` → `avmdec`）。「別ファイル」では IVF と音声ファイルができ、IVF はコマンドラインと同じバイト列。
- 進み具合が1秒以上止まらずに更新され、中止は2秒以内に効く。
- 空白や日本語を含むパスでも動く。
- 配布用の zip を別のフォルダに展開し、追加インストールなしで動く（この PC で確かめる）。
- 自動テストがすべて通る。

## 範囲外

- 10 ビット / HDR での符号化（CelV2 本体の作業。備えだけ今回行う）
- MP4Box の同梱、mkv など MP4 以外の入れ物
- AviUtl2 のプラグイン
- インストーラー、コード署名
- 変換待ちの一覧の保存、プレビュー
