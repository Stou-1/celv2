## 項目ごとの結果

### 1. シーンカットでキーフレーム（dbc2ae9）

- 8x8 の平均で前の画像との差を取る。差が 20 を超え、直近 8 枚の中央値の 4 倍を超え、次の画像では差が半分未満になり、2 枚前との差も 20 を超えるときにカットとする。1 枚だけのフラッシュや、カットの間の黒い画像はカットにしない。
- 5087 枚で 49 か所をカットと判定した。
- 全体 −1.1%。カットの多い e は −3.8%、f は −1.9%。f の q45 では、サイズ −3.7% で、最も悪いフレームが +1.8 dB 良くなった。
- `--keyint` は最後のキーフレームから数えるように変えた。

### 2. イントラ強化（afd01f5）

- 輝度モードを 5 から 13 に増やした。方向性の 8 モードにはそれぞれ角度差 ±3 がある。エンコーダ側で、13 モードを角度差 0 で試し、最良の方向性モードの角度差を試して選ぶ。
- 内訳: エッジフィルタ + IBP だけでは ±0。探索だけで −1.6 / −0.8%。新モードのビット見積もりを 3 / 6 / 9 にすると +2.3 / −1.2 / −1.6%。
- 見つけた不具合: IBP の重みは、デコーダと同じく `init_ibp_info` で初期化する必要がある。

### 3. 変換サイズ選択（不採用）

- ブロックごとに NONE / SPLIT / HORZ / VERT を、実際の変換、RDOQ、再構成を試して選んだ（SSE + λ × 推定ビット）。デコーダとはビット単位で一致した。
- ビットの重み 1 倍で +0.41 / −0.56%、0.5 倍で 0.00 / −0.63%、0.25 倍で −0.49 / −0.79%。
- 速度が 0.62 倍になるのに、効果は 1% 未満のため戻した。

### 4. 複合予測（d8bb8f2）

- 参照ごとに最良の候補を出し、上位 2 つの参照の平均を SATD で比べる。
- 複合のビット見積もりが 3 / 6 / 10 / 14 / 20 のとき +1.2 / −1.2 / −1.9 / −1.9 / −2.2% で、20 を採った。

### 5. B フレーム（d125ca1、GUI は 46e2076）

- 構成: 次の参照フレームを先に隠して符号化し（immediate_output_picture = 0）、その間の N 枚を両側から予測する（N 枚は参照にしない）。最後に show-existing-frame の OBU で隠した 1 枚を出す。1 つの時間単位が必ず 1 枚を出すので、IVF / MP4 の時刻はそのまま使える。MP4（av2_mux）経由で復号しても 48 枚すべてが復元画像と一致した。
- qindex をすべて同じにすると、1 / 3 / 7 枚で +9.6 / +22 / +37% と悪化した。
- B に +16、隠し参照に −16 の固定差を付けると、2 枚で −6.54%（全域）。高画質域では 1 枚でも +5.55%。
- 割合で差を付ける方式（±12%）は、2 枚で −5.16%（高画質域 +7.15%）、3 枚で −1.12%（同 +16.46%）で、固定差より悪かった。
- 上の数値は、下の「6.」で直した不具合が残っていたときのもの。直した後の数値と既定は「6.」を参照。

### 6. レビューで見つかった不具合（ffc5252）

チームレビュー（scout → bug-hunter → verifier）で、どちらも「復号は AVM と一致したまま、圧縮効率だけが落ちる」不具合が 2 件見つかった。既存のテストは復号の一致しか見ないので、見つからなかった。

- **複合予測の MV が逆の参照に付いていた**: 判定は「単独で最良の参照」を ref、2 番目を ref2 として出す。書き込み側は参照を番号順に並べ替えるが、MV は並べ替えていなかった。そのため、ref の番号が大きいブロック（複合ブロックの約 36%）では、2 つの参照がそれぞれ相手の MV でずらされていた。直すと、B フレームなしで −4.0%。B フレームでは前後の参照で MV の向きが逆になるので、影響がさらに大きかった。B フレーム 2 枚の効果は −6.5% から −13.5% に、高画質域では +5.6%（逆効果）から −6.4% に変わった。
- **B フレーム使用時、表示番号が 128 枚ごとに 0 へ戻っていた**: AV2 の表示番号は、スロットにある「表示済みのフレーム」から導出される。隠し参照だけを参照にしていたので、その基準が 0 のまま止まり、128 枚ごとに約 12 枚、参照の順位が逆になっていた。表示した B フレームを、上のスロット（それまで最新の参照の複製を置いていた所）に置くようにした。参照の候補は 1 枚増える（refs + 1、最大 7）。

B フレームの枚数（不具合修正後、B フレーム 0 枚との比較）:

| 枚数 | q45〜180 | q30〜75 |
|---|---|---|
| 1 | — | −6.1% |
| 2 | −13.5% | −6.4% |

これを受けて、`celv2enc` の既定を `--bframes 2` にし、GUI は高画質を含む全プリセットで 2 枚にした。

## 残っている課題

- ヘッダを変えても、依存するオブジェクトが再ビルドされないことがある。古いオブジェクトのせいで、GPU と CPU の判定の不一致や、`--device cpu` のクラッシュが起きた。全ソースを触ってから再ビルドすれば直る。
- AV1 との差はまだ大きい（別のレポートで計測する）。
