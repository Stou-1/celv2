# CelV2 と AV1（SVT-AV1 preset 0 / libaom cpu-used 0）の差（2026-11-02）

## 結論

- CelV2（fix/rd-pass-dc, a886385）は、AV1 の最も遅い設定より **+30〜+84%** 大きい（同じ画質で）。差がいちばん大きいのは動きの多いアニメ（chika +73%、Dragon Maid +64〜83%）で、小さいのは AMBITIOUS MISSION（+30%）と AIR（+29〜33%）。
- 以前の比較で Dragon Maid / AIR / chika / 吉村 が AV1 より小さく見えたのは誤り。保存していた AV1 の出力（fhd_a_*）が、CelV2 と別のフレームから作られていた（可変フレームレートや時刻の半端な素材）。同じ y4m から作り直した（fhd_b_*）。
- 1 枚ずつの PSNR を見ると、どのフレームでも SVT の方が高く、上がり下がりの位置も揃っている。フレームのずれではない。

## 計測条件

| 項目 | 内容 |
|---|---|
| 素材 | 各 1920x1080 の 120 フレーム（g_<素材>.y4m） |
| CelV2 | `--qindex 100/130/160/190 --refs 7 --keyint 240`、アニメは `--tune animation` |
| AV1 | ffmpeg の libsvtav1 preset 0 / libaom-av1 cpu-used 0、q 20/32/44/56（av1bench.py の設定） |
| 画質 | ffmpeg psnr の全体 MSE による PSNR-Y（フレームの平均ではない）。フレームは番号で対応させる（settb=1/30,setpts=N） |

## その後: 動き探索の届く範囲（2026-11-02）

- 同じツールの avmenc（cpu-used 6）と比べると、Dragon Maid だけ +41% と大きく、フレームごとの PSNR はほぼ同じでバイト数が 33% 多かった。GOP の長さ（`--bframes 7`: −0.08%）、キーフレームの qindex（`--kq 0`: 素材で ±2%）、キーフレームの時間フィルタ（悪化）では説明できなかった。
- GPU の動き探索は 3 段のピラミッドで ±52 画素ほどしか届かなかった。5 段（±250 画素ほど）にすると、Dragon Maid −10.0%、Angel Beats −5.1%、park_joy −1.3%、AMBITIOUS MISSION −1.2%、chika −0.9%、crowd_run −0.2%、吉村 +0.1%、AIR +0.8%。速さは変わらない（Dragon Maid q130 で 28.2 秒と 28.3 秒）。4 段で 1 段 ±16 も平均 −2.2% だが、AIR が +1.2% と悪い。
- AVM にあって CelV2 にないツール（拡張分割、SDP、IBP、DIP、パレット、TIP、オプティカルフロー、joint MVD）は、avmenc 上でどれも ±1% 以内だった（33 フレーム、AMBITIOUS MISSION / Dragon Maid / 吉村）。差はツールではなく探索と判定にある。

## avmenc と同じツールで比べる（33 フレーム、2026-11-02 の main d656bb6）

avmenc を CelV2 のツールに絞り（gap/avmabl.py の base）、cpu-used 6 と 0 で符号化したものとの BD-rate（正は CelV2 が大きい）。

| 素材 | avmenc cpu-used 6 | avmenc cpu-used 0 | avmenc 自身の 6 → 0 |
|---|---|---|---|
| AMBITIOUS MISSION | +12.7% | +32.7% | −17.0% |
| Dragon Maid | +26.9% | +60.1% | −21.9% |
| 実写（吉村） | −27.1% | −11.8% | −14.9% |

avmenc でも探索を深くする（cpu-used 6 → 0）と 15〜22% 小さくなり、どのツールの追加（±1% 以内）よりずっと大きい。CelV2 に残る差も探索と判定にある。
