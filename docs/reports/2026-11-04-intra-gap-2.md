# イントラの差、2 回目：段階 0 の計測（2026-11-04）

設計書：docs/superpowers/specs/2026-11-04-intra-gap-design.md の段階 0。前回は docs/reports/2026-11-03-intra-rd.md。

## 結論

- **差は粗い側ほど大きい。** CelV2（HEAD、72ceb99 時点）は avmenc cpu-used 6（CelV2 と同じ道具）と同じ PSNR-Y で、q100 では −6〜+18%、q190 では +25〜+49% 大きい。7 フレームの平均は +10〜+31%。
- **差の一番大きい部分は係数のビット**（7 フレーム中 5 つで、avmenc のビットの +7〜+27%）。次が分割（+2〜+6%）。
- **avmenc との作りの違い**（q130）：
  - 輝度の変換の分割：CelV2 は面積の 4〜16% を分割、avmenc は 0%。
  - 128 のブロック：avmenc は面積の 10〜20%（Dragon Maid は 93%）、CelV2 は 0%。
  - 信号する alpha の CfL（`CFL_EXPLICIT`）：avmenc は面積の 1〜17%、CelV2 は持たない。導き出す alpha の CfL は両方とも広く使う。
  - IDTX：avmenc でも 0〜3%。CelV2 の候補に足す必要は小さい。
- **直す順番**（設計書の「差の大きい順」）：
  1. 修正 2（変換の分割を、モードと同じ RD で決める）：係数のビットの差に直接効く。
  2. 修正 3（128 のブロック）：分割のビットと、Dragon Maid のような平らな絵に効く。
  3. 修正 1（CfL の RD と、信号する alpha）：色差のモードのビットは、もう CelV2 の方が少ない。色差の係数がどれだけ減るかで決まる。

## 条件

- フレーム（1 枚ずつ、`celv2-bench\intra-gap\frames`）：Flash 20 秒・100 秒の 0 枚目（1440x1080）、AIR OP 60 枚目、AM 0 枚目、Dragon Maid 0 枚目、chika 0 枚目、吉村 0 枚目（実写）。
- avmenc：`--good --cpu-used=6 --end-usage=q --qp=100|130|160|190 --limit=1 --bit-depth=10`、CelV2 にない道具はオフ（2026-11-03 の調査と同じ一覧）。アニメは CfL オン・MHCCP オフ（CelV2 の `--tune animation` と同じ）。吉村は CfL と MHCCP の両方がオン（CelV2 の既定は MHCCP だけだが、avmenc は CfL なしで MHCCP を使えない）。
- CelV2：`--qindex` を二分探索して、avmenc の各点の PSNR-Y に合わせる（アニメは `--tune animation`）。既定の 10 ビットで符号化。
- PSNR-Y は 10 ビットで（8 ビットの元は ×4）。ビットの内訳と面積は、AVM の復号器の計数（`tools/acct.c`、CfL の種類と変換の種類の面積を足した）。
- スクリプトと結果：`celv2-bench\intra-gap\tools\stage0.py`、`stage0_table.py`、結果 `s0\rows.json`。

## 修正 2（変換の分割）の結果：効果なし、入れない

- `--intra-txp-rd 1` を作った：分割の記号を実際の確率で数え、変換ブロックごとの「すべて 0」の旗と end of block を足す（end of block は大まかに 1 + 2.5 + 位置の余りのビット）。その重みを変えて、7 フレーム q100〜190 の PSNR-Y BD-rate（`--intra-txp-rd 0` に対して）：

| 重み | 0 | 0.02 | 0.05 | 0.2 | 0.5 | 分割しない |
|---|---|---|---|---|---|---|
| 平均 | +1.71% | +0.14% | −0.03% | +1.27% | +2.02% | +6.00% |

- いまの大まかな値（分割しない 1 ビット、する 4 ビット、重み 0.2）が、すでに一番良いところにある。分割を高くつけるほど悪くなり、分割をやめると Dragon Maid で +28.7%。
- avmenc は分割しないが、CelV2 の係数のビットの差は分割から来ていない。コードは戻し、tried-not-kept に記録した。
- 変換の種類：IDTX は avmenc でも 0〜3% なので、候補に足さない。
- 次は修正 3（128 のブロック）。

## 修正 3（128 のブロック）の結果：効果なし、入れない

- 作り：RD パスの後、1 つの 128 の超ブロックの中の 4 つの 64x64 がどれも「分割なしのイントラ 1 ブロック」なら、1 つの 128x128 のイントラ（全モード、変換は 64x64 に分けて分割なし）と比べ、安い方にする。符号化側のモードの見積もりも、128 のブロックでは 4 つの 64x64 の単位すべてを見るようにした。
- 7 フレーム q100〜190 の PSNR-Y BD-rate（`--intra128 0` に対して）：平均 +1.4〜+1.8%。Dragon Maid +9.4〜+29.6%、ほかは −0.3〜+0.8%。比の値（1.0〜2）、モードを RD パスのまま使う、「係数がすべて 0 になる単位だけ」にしぼる、のどれでも Dragon Maid の損は消えなかった。
- 原因：Dragon Maid の画面の上の端は、縦に急な明るさの変化（上 64 行で 544 → 940）がある。RD パスの見積もりは原画の端から予測するので、横方向の予測でほぼ 0 の残差に見える。実際の AV2 は、128 のブロックの中の 64x64 の単位ごとに、復元した（端をなめらかにした）隣から予測し、しかも変換を分割できない。そのため上の 16 行が約 8 段ずれた（ループフィルターを切ると上 16 行の MSE 179、64x64 のときは 5.9）。64x64 のブロックは、そこで変換を分割して避けていた。
- 符号化側の情報（復元した隣）なしに RD パスでは見分けられない。入れるなら、128 のブロックを試しに符号化して比べる作りが要る（tried-not-kept に記録）。
- インターフレームの 128 のブロック（設計書の条件付きの部分）：イントラで効果がなかったので、avmenc の 4K / 8K / 16K の計測は後回しにする。

## 修正 1（CfL）の前に

- 修正 2・3 とも効果がなく、表 1 の「係数のビット」の差は、分割でも 128 でもない。残る候補は、CfL（色差の係数）、量子化（avmenc の RDOQ）、イントラの予測そのもの（avmenc は IST などを含めて選ぶ）。

## 修正 1（CfL を RD で選ぶ、信号する alpha）の結果：既定に入れる（`--cfl-rd 1`）

- 作り：
  1. 輝度のモードが決まったら、そのブロックの輝度を一度復元する（変換の分割の選び方と同じ DCT の量子化。選んだ分割はそのまま符号化に使う）。CfL と MHCCP の見積もりは、原画の輝度ではなくこの復元から予測する。1.2 倍の係数は 1 にした。
  2. 色差の候補（SATD で上位 4 つのモード、導出 alpha の CfL、MHCCP の一番良い方向）を、U と V の量子化のコストとモードのビット ×0.05 で選び直す。
  3. 信号する alpha（`CFL_EXPLICIT`）：導出 alpha を 1/8 単位に丸めた値と、U・V それぞれ ±1 の 9 通りまでを同じコストで比べる。結合した符号と、平面ごとの大きさを AV2 のとおりに書く。
- 1 フレーム（7 フレーム q100〜190、Y / YUV 6:1:1、`--cfl-rd 0` に対して）：手順 1 だけで +0.13 / −0.53%、手順 2 まで −0.45 / −2.76%、手順 3 まで −0.14 / −3.15%。
- **120 フレーム**（8 素材、`--refs 7`、q100〜190、全体の MSE の PSNR）：

| 素材 | Y | YUV 6:1:1 |
|---|---|---|
| AIR | +0.17% | −0.36% |
| Dragon Maid | +0.09% | −0.27% |
| AM | −0.23% | −0.78% |
| chika | +0.01% | −1.21% |
| Angel Beats | −0.17% | −1.62% |
| 吉村 | +0.03% | −2.20% |
| crowd_run | −0.03% | −0.19% |
| park_joy | −0.03% | −0.08% |
| 平均 | −0.02% | −0.84% |

- 設計書の判定（平均が負、どの素材も +0.5% を超えない）を満たす。YUV ではすべての素材で良くなる。
- 速さ：符号化の時間は 0.88〜1.01 倍（AV1 の比較が CPU を埋めている中の計測。遅くはなっていない）。
- 次：実写で CfL を既定にするか（設計書：吉村・crowd_run・park_joy で Y +0.2% 以内、YUV が負なら）を測る。

## 実写でも CfL を既定に（`--cfl 1`）

- `--cfl-rd 1` の上で、`--cfl 1` を `--cfl 0` と比べた（120 フレーム、`--refs 7`、q100〜190。`--cfl 1` では MHCCP が既定でオフになる）：吉村 +0.10 / −0.66%、crowd_run +0.04 / −0.13%、park_joy +0.03 / −0.09%（Y / YUV 6:1:1）。
- 設計書の条件（3 つとも Y +0.2% 以内、YUV が負）を満たすので、`--tune` によらず既定にした。
- MHCCP を CfL と一緒に使う組み合わせ（tried-not-kept の「色差の見積もりが復元した輝度を使うようになったら」）を測り直した（CfL だけに対して Y / YUV）：AIR −0.05 / −0.44%、AM −0.24 / −0.49%、Angel Beats −0.08 / −0.17%、Dragon Maid・chika は 0.1% 以内、吉村 −0.11 / +0.52%、crowd_run・park_joy は 0.05% 以内。アニメでは YUV がすべて負なので `--tune animation` で既定に、実写は吉村の色差が悪くなるのでオフのまま。
