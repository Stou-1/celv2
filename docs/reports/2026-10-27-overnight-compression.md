## B フレーム並列

- 結果は逐次と同一バイト（`bframe_group_matches_sequential` で検証）。
- 速度: 4K 8.2 → 8.9 fps、8K 変化なし、16K 1.55 → 1.44 fps（判定が GPU で順番に走るため律速）。
- そこで `--parallel-b auto`（既定）: 4K×2 画素まで並列。それより大きいと従来の構造のまま
  （サイズ増なし）。
- 並列時のサイズ増（+1.4% / +3.2%）は上の改善で補填済み。

  次の手: ブロックサイズ間で 4x4 SATD を使い回す（設計変更が必要）。
- `--refs 2` なら 16K で約 1.86 fps（アニメ 6 クリップで +1.2% / +0.2%）。既定は変えていない。

## 試して不採用

- GPU 判定に MV の差分ビットを加える: +6〜11%（イントラ化・分割が増える）。
- デブロック強度オフセット: 最終版で +2 が −0.7% / −0.1%（全クリップで改善）なので既定にした（+4 は効果なし）。
- キーフレーム qindex オフセット −24〜−32: −0.2〜−1.0%、ただしクリップ f で +9%。`--kq` として残す（既定 0）。
- B / ALT の qindex オフセット変更、複合予測コスト、ME ペナルティ: ±1% 以内。
- DRL 候補 3 ビット: −0.7%。
- B フレーム数 3 / 4: −0.5% / +1.2%（高画質域 +0.7% / +4.3%）。
- NEARMV 判定の差分ビット重み ×2 / ×0.5: +6.1% / −0.3%。
