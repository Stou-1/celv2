# 16K の VRAM と、1/4 画素の面の持ち方（選択肢 A〜D）（2026-11-04）

速さの財源づくりの設計書（docs/superpowers/specs/2026-11-04-speed-budget-design.md）が「16K の実測の後に書く」とした、エンジンの VRAM を減らす設計の材料。

## 結論

- いまの作り（参照ごとに 1/4 画素の 16 面）の 16K での VRAM の最大使用量：RTX 5090 16.48 GB、Arc Pro B50 14.54 GB（16 GB のほぼ全部）。設計書の見積もり約 15 GB に近い。
- **選択肢 B（半画素の 4 面だけ持ち、残りは読むときに補間）が、VRAM・時間とも良い**：VRAM 7.6 GB（−54%）、RTX 5090 の判定エンジン −7%（1172 → 1086 ms/frame）、B50 の符号化全体 −15%（21.0 → 17.8 s/frame）。B50 の判定エンジンだけなら +10%（8052 → 8893 ms）。
- 選択肢 A（面を持たない）は VRAM 5.4 GB（−67%）だが、判定エンジンが 5090 で +9%、B50 で +28%。
- 選択肢 C（近い 2 枚だけ 16 面）は VRAM 9.3 GB、B50 の判定エンジン +21%（参照 4 枚）。D（行の周りの帯）は VRAM 5.6 GB、B50 の判定エンジン +67%（同）。どちらも B に及ばない（下の「C と D」）。
- どの持ち方でも、同じ判断（同じバイト列）。RTX 5090・B50 とも確認（test_cli `cli_vk_phase_layouts`、吉村 12 フレームの符号化）。

## 計測

- 素材：a16k（15360x8640、9 フレーム）。
- VRAM：`celv2enc --refs 7 --qindex 130 --device vulkan|vulkan2` の全体の符号化を、Windows の性能カウンター「GPU Process Memory(pid_*)\Dedicated Usage」で 0.5 秒ごとに読み、その最大。
- 判定エンジンの時間：tools/engine_bench（エンジンだけ、参照 2 枚、4 フレーム目以降の平均）。
- 切り替え：`CELV2_VK_PHASES=A|B`（計測用の環境変数。既定は 16 面のまま）。

| 持ち方 | VRAM 最大 5090 / B50 | 符号化 5090 / B50 | 判定エンジン 5090 / B50 |
|---|---|---|---|
| 16 面（いま） | 16.48 / 14.54 GB | 5.4 / 21.0 s/frame | 1172 / 8052 ms |
| A：面を持たない | 5.36 / 5.38 GB | 5.5 / 20.7 s/frame | 1277 / 10335 ms |
| B：半画素の 4 面 | 7.59 / 7.61 GB | 5.4 / 17.8 s/frame | 1086 / 8893 ms |

- 同じ実行での CUDA エンジンの時間（持ち方の切り替えは Vulkan だけ）：1092 / 1180 / 1083 ms。測るたびのばらつきは ±8% ほどある。
- B50 の 16 面は VRAM がほぼいっぱいで、符号化全体が遅かった（14.54 GB）。B で余裕ができ、符号化全体が速くなったと見ている。

## 作り（計測用）

- `common.slang` の `Plane::at_q()`：`phase` の上位ビットで持ち方を表す。A は 1/4 画素の位置を読むたびに `subpel_px()` で補間、B は半画素（(qy, qx) が偶数）の 3 面と元の面の 4 面だけ持ち、残りを補間。補間した値は、あらかじめ作った面の値と同じ（端の扱いも同じ）。
- `subpel.slang`：B では半画素の 3 面（位相 2、8、10）だけ作る。

## C と D（2026-11-04 午後に実装して計測、bd2edea）

- **C（近い参照 2 枚だけ 16 面、残りは A）**：16 面の置き場を 2 つ持ち、その起動で一番近い 2 枚の参照を参照の番号で入れておく。ほかの参照は読むたびに補間。
- **D（処理中の超ブロック行の周りだけ面を持つ）**：参照ごとに、1 面のあとに「超ブロック 1 行 ＋ 上下 64 行」分の位相 1〜15 の帯を持ち、各行の前に作り直す。帯の外と、動き探索の 1/4 画素の詰め（行より前にフレーム全体で走る）は補間。
- どちらも同じバイト列（a16k の全体の符号化 9 フレームで 5 通りとも MD5 83E9AE1D、5090・B50 とも。小さい素材と吉村 1080p `--refs 7` でも一致。D は上下 0 行でも一致）。

| 持ち方 | VRAM 最大 5090 / B50 | 符号化 5090 / B50 | 判定エンジン B50、参照 2 / 4 枚 |
|---|---|---|---|
| 16 面（いま） | 16.48 / 14.55 GB | 10.8 / 24.8 s/frame | 8211 / 12848 ms |
| A：面を持たない | 5.36 / 5.39 GB | 10.7 / 23.8 s/frame | 10641（+30%） / 16918（+32%） |
| B：半画素の 4 面 | 7.59 / 7.61 GB | 10.8 / 20.9 s/frame | 9167（+12%） / 14381（+12%） |
| C：近い 2 枚だけ 16 面 | 9.32 / 9.35 GB | 10.5 / 21.8 s/frame | 8603（+5%） / 15555（+21%） |
| D：行の周りの帯 | 5.61 / 5.63 GB | 9.5 / 26.9 s/frame | 12456（+52%） / 21419（+67%） |

- 午後の計測は、AV1 との比較（avmenc 約 50 本）が CPU を埋めている中で行った。符号化全体の時間は朝の値（5.4 / 21.0 s/frame）より遅く、持ち方どうしの比較だけに使える。
- 判定エンジンの時間は tools/engine_bench（参照の枚数を指定できるようにした）。RTX 5090 の値は、持ち方に関係しない CUDA エンジンの時間が同じ実行の中で 1067〜1709 ms とばらついたので、表に入れていない（CPU が空いたときに測り直す）。B50 は GPU の時間が大半で、朝の A・B の値（+28%、+10%）と合う。
- **C** は、参照 2 枚なら 16 面と同じ作りなので速いが、参照 4 枚では B より遅く、VRAM も B より多い。近い 2 枚が起動ごとに入れ替わり、そのたびに 16 面を作り直すため。
- **D** は VRAM が A に近い（帯の分 +0.25 GB）が、一番遅い。行ごとに参照の数だけ帯を作り直し、帯は上下に重なるので、フレーム全体の面を作るより約 3 倍の計算になる。行の順に帯をずらして作り足す形にすれば減らせるが、行を並べて流す（row streams）ときは行が飛ぶので効きにくい。

## 設計側への提案

- B を既定にする（VRAM の予算に関係なく）のが良さそう。5090 で速くなり、B50 では符号化全体が速くなる。C・D を測った後も変わらない：C は VRAM・時間とも B に負け、D は VRAM で B に勝つが時間で大きく負ける。
- 判定エンジンだけの時間で B50 が +10% になる分は、設計書の段階 C（Vulkan エンジンの改善）で取り返す対象。
- A は VRAM がもっと足りない GPU（8 GB 級）向けの予備。

## 全体の速さの確認と、決めた規則（2026-11-05）

設計書の「4 面を既定にする前に、S1 と S3 を両方の GPU で計る」の結果。**全体が 1% を超えて遅くなったので、設計書の分岐どおり、小さいフレームは 16 面のままにした。** どの持ち方でも同じバイト列。gap33（avmenc 6 本）の負荷の中で、16 面と 4 面を交互に計った。

| 素材 | RTX 5090 16 面 / 4 面 | Arc Pro B50 16 面 / 4 面 |
|---|---|---|
| S1（1080p） | 9.44 / 5.42 fps（−43%） | 1.40 / 0.78 fps（−45%） |
| S3（4K） | 2.09 / 1.80 fps（−14%） | 0.42 / 0.26 fps（−38%） |
| 8K（9 フレーム） | 1.90 / 1.95 s/frame（+2%） | 4.6 / 5.4 s/frame（+17%） |
| a16k（9 フレーム） | 7.3 / 7.1 s/frame | 23.1 / 19.4 s/frame（−16%） |

- S1、S3 の 5090 は 3 回の平均（4 面は 5.04〜5.65 fps、1.71〜1.97 fps と揺れる）、B50 は 1 回。8K と 16K は 2 回の平均。差が大きいので、負荷のせいではない。
- 判定エンジンだけの時間（16K）では +10% ほどでも、1080p では全体の律速が判定エンジンに移るので、全体が大きく落ちる。

**規則（`vk_phase_layout()`）：** 8192 x 8192 画素未満は 16 面、それ以上は 4 面。空き VRAM に入らなければ 4 面、面なし（A）の順に落とし、それでも入らなければ `--device auto` は CPU エンジン、明示の `--device vulkan` はエラー。必要な量は、参照 7 枚分の面と、その他 1 画素 35 バイト（16K の 4.6 GB から）の見積もり。8K と 16K の間は計っていない。

C と D は消した（tried-not-kept に記録）。`CELV2_VK_PHASES` は A、B、16 をテスト用に残した。

**まだ計っていないもの（設計書の残り）：** 参照 7 枚を持つ長い 16K の素材の VRAM（両方の GPU）、その他 4.6 GB の内訳、静かな CPU での 5090 の判定エンジンの時間。
