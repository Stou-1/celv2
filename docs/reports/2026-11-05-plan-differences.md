# 計画と違った結果の一覧（設計担当へ、2026-11-05）

2026-11-04 の設計書 9 つを実装して計測した中で、設計書と結果が違ったものの一覧。ブランチ feat/intra-rd、0d9d6cf 時点。詳しい数字は各行の報告書にある。AV1 との差の内訳（設計書 3）は gap33 の完了待ちで、ここには入っていない。

BD-rate はマイナスが良い。

## 設計担当に決めてほしいこと

1. **`--warp` の段階 B を書くか。** 条件は 2 つとも満たした（下の 1-1）。ただし CelV2 が伸びない原因は未確定で、GPU で探索しても直るとは限らない。先に「skip mode と compound のブロックでも warp を試す」を CPU で確かめる手もある。
2. **Flash の目標 −10% を変えるか。** avmenc 自身が q100〜190 で −9.62%（warp）なので、warp の目標は avmenc の効果の全部を求めている。
3. **`--screen` を既定にする条件。** `auto` は悪化 +0.02% 以内だが、速度が未計測。周期の判定の基準 0.4 は Angel Beats の 1 枚だけで決めた。
4. **網点のフレームをどう扱うか。** B1 の本来の的だが効いていない。RD パスで評価すると効くが、Angel Beats が壊れる（1-4）。RD パスが符号化器の判断を知る方法が要る。
5. **`--paq` の速度の判定。** 報告書は 1.03〜1.14 倍、台帳は CPU +0.9%。どちらで判定するか。
6. **CUDA の削除の時期。** 手順 4 はリリースの後。リリースはユーザーの指示待ち。

## 3. 設計書と違う判断をしたもの

| # | 項目 | 設計書 | 実際にしたこと | 理由 |
|---|---|---|---|---|
| 3-1 | `--screen` B1 のコピー | RD パスと符号化器で評価 | 符号化器だけ。128 bit を上乗せ | RD パスに入れると Angel Beats が x1 で +46.68%、x2.5 で +1.10%。上乗せは輝度のコストに入らない色差の分 |
| 3-2 | `--screen auto` の判定 | パレットと繰り返しの割合 | パレットの割合だけ。周期のブロックが 40% 以上のキーフレームを追加 | 繰り返しの割合は Flash と通常ソースで重なる |
| 3-3 | `--warp` 段階 A | フレームの判定、RD パスでの評価、6 パラメータ | どれも入れず | 判定する効果がない。RD パスでの評価は試して悪化（+0.48%、+1.70%） |
| 3-4 | `--warp` 段階 B の集計 | SATD で比較 | 符号化器の RD コストで比較 | 符号化器が比べる値に合わせた |
| 3-5 | `test_vk_kernels` | CPU 参照と比較 | イントラのコストだけ。インターのコストと判定はエンジン全体の比較に任せた | 個別の CPU 参照がない |
| 3-6 | 速度の計測 | CPU が空いた状態 | gap33 の負荷の中で計測 | gap33 が終わらないため。比較には使えるが、値そのものは悪く出る |

## 4. まだ判定できていないもの

- `--screen` の速度（上限 3%）と `--warp` の速度（上限 5%）。gap33 の完了後に計る。
- 速さの財源づくりの S2 の Angel Beats。素材がこのマシンにない。
- `--warp` が伸びない原因。分かっているのは、探索が Flash の面積の 19% にしか届いていないこと（skip mode と compound では試さない）、隣のブロックのモデルを受け継ぐ流れが始まらないこと。探索の不具合を直しても変わらなかった。
- 次に直す候補へ足すもの：係数のないブロックのモード情報がストリームの 18〜24%、ブロック数が avmenc の 2〜3 倍（画質はそろえていない）。`skip_txfm` を使わない分は 0.6〜0.9% が上限。AV1 との差の内訳の報告書に入れる。
