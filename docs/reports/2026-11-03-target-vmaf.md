# `--target-vmaf`：シーンごとに VMAF を合わせる（2026-11-03）

## 結論

- `--target-vmaf 93` で、8 本の素材の 20 シーンすべてが VMAF 93.0〜93.55 に入った（狙いを 0.5 以上下回ったシーンなし）。
- 「どのシーンも 93 を下回らない」を 1 つの qindex で満たすときと比べて、シーンが複数ある素材で −5〜−72% 小さい（Flash −71.6%、カットの多い AM 600 フレーム −31.2%、AM −29.9%、Dragon Maid −10.5%、Angel Beats −5.0%）。1 シーンだけの素材は ±2% 以内。
- 時間は 1 つの qindex の 1.4〜5.1 倍（ほとんど 3.6〜4.9 倍）。
- GUI の「画質指定（VMAF、0 = オフ）」欄から使える。サイズ指定とはどちらか一方。

- VMAF は vmaf_v0.6.1 の各フレームの平均（ffmpeg libvmaf）。1 つの qindex の値は qindex 110 / 130 / 150 / 170 / 190 の符号化からバイト数の対数で補間した。
- 平均 VMAF をそろえる比べ方では、1 つの qindex は難しいシーンを 93 より下にする代わりに易しいシーンで稼ぐので、カットの多い素材では 1 つの qindex の方が小さい（+11.8%）。この機能はどのシーンも狙いを下回らないためのもので、比べるべきは一番悪いシーンをそろえた方。

## 作り（docs/superpowers/specs/2026-11-03-target-vmaf-design.md）

- シーン（48 フレーム以上のチャンク）ごとに、同じ設定のまま qindex を変えて試し符号化し、ffmpeg の libvmaf で測る。最初は `--qindex`、2 回目は log(100 − VMAF) の典型的な傾き（qindex 1 あたり 0.017）で狙いへ、その先は両側の 2 点を結ぶ直線との交点。狙いの 0.15 以内に当たったら止める。普通は 4 回まで、4 回目でも狙いより 1.0 以上高ければ 5 回目。
- 結果は「試した中で狙いを満たす一番高い qindex」。128 フレーム以下のチャンクは丸ごと試すので、その試しの出力をそのまま使う（VMAF は測った値そのもの）。長いチャンクは先頭 96 フレームで試してから符号化し直す。
- チャンク同士は待ち合わせないので、worker の数を変えても同じバイト数になる（test_cli cli_target_vmaf）。

## 試して外したもの

| 試したこと | 結果 |
|---|---|
| フレームを間引いて試す（2 枚に 1 枚、最大 48 枚、pass 1 の速い設定） | 各シーン 92.3〜95.0、Dragon Maid の 1 シーンは 89.9。間引くとフレームの間隔が開いて予測が効かず、同じ qindex でもビットが増えて VMAF が高く出る（Dragon Maid 0〜72、qindex 172：全部で 89.9、間引いて 94.9） |
| 4 枚に 1 枚（最大 24 枚） | 91.4〜91.7 |
| 8 / 16 フレームの塊をキーフレームから | 92.9〜94.7 |
| 試しを RD パスなしにする | 同じ qindex で VMAF が約 1.8 低い |
| 試しを 8×8 タイルにする | VMAF は変わらず速いが、丸ごと試して出力を使い回す方が速い |
| 前のシーンの qindex から始める（前のチャンクを待つ） | 試しの回数は減らなかった |
| 止める幅 0.3 | chika で +5.2%（VMAF 0.3 が qindex 約 2） |
| 区間の両端から 1/4 内側に次の試しを置く | 吉村 +22.7%、Angel Beats +0.9%（狙いに寄り切れない） |
| 試しは 4 回まで（5 回目なし） | Flash の 1 シーンが 98.3（qindex 168 の次が 190 で 90.7、4 回で終わり）、Flash 全体 −64.6% |
