# CelV2 v0.3.0 リリースノート

> **注意（再生）：2026 年 10 月までの dav2d（例：3812a7a）では、CelV2 v0.3 のストリームを正しく復号できません。** 途中で異常終了するか、映像が崩れます。upstream の main 9b5cef2（2026-11-12）以降なら、改造なしで正しく復号できます。下の「dav2d で再生するには」を見てください。

## 圧縮

v0.2.0 と比べて、同じ画質でサイズが平均 8.51% 小さくなりました（PSNR-YUV 6:1:1。PSNR-Y では 6.49%、SSIMULACRA2 では 5.71%）。8 素材すべてで小さくなっています。

| 素材 | PSNR-YUV | PSNR-Y | SSIMULACRA2 |
|---|---|---|---|
| Angel Beats | -11.83% | -9.95% | -5.62% |
| AM | -10.98% | -7.12% | -9.06% |
| park_joy | -9.23% | -7.01% | -7.77% |
| 吉村 | -8.72% | -5.98% | -5.32% |
| crowd_run | -7.97% | -5.78% | -8.06% |
| chika | -7.26% | -5.78% | -1.57% |
| Dragon Maid | -6.53% | -5.85% | -4.39% |
| AIR | -5.54% | -4.47% | -3.88% |
| **平均** | **-8.51%** | **-6.49%** | **-5.71%** |

120 フレーム 1080p、qindex 100〜190 の 4 点、BD-rate（− が小さい）。アニメは `--tune animation`、実写は tune なし。両方 `--refs 7 --workers auto`、
ほかはそれぞれの版の既定（v0.2.0 には `--real-trellis` がない）。PSNR は各面の全フレームの MSE から。
SSIMULACRA2 は 4 フレームに 1 枚（30 枚）を採点した 3 次式の BD です。
chika の SSIMULACRA2 はあまり縮んでいません（-1.57%。PSNR-YUV では -7.26%）。

### AV1 との差（正直な数字）

まだ AV1 の最良のエンコーダより大きいです。同じ 8 素材で、同じ画質に要るサイズ（+ は CelV2 が大きい）：

| 相手 | PSNR-YUV | PSNR-Y | SSIMULACRA2 |
|---|---|---|---|
| SVT-AV1 4.2.0 preset 0（10 ビット） | +33.9% | +19.0% | +36.8% |
| libaom cpu-used 0（10 ビット） | +40.3% | +29.4% | +30.7% |
| SVT-AV1 preset 2（10 ビット） | +20.0% | +6.1% | +21.7% |

SVT-AV1 preset 0 との差は素材で +14%（アニメ 2 本）から +68%（グレインの多い実写）まで開きます。

## 速さ

v0.2.0 より速くなりました。CPU の時間は、AVX-512 のある CPU でフレームあたり 35〜41%、AVX2 だけの経路で 27〜35% 減っています（% は表の v0.2.0 の列に対して）。

| 素材 | | v0.2.0 | v0.3.0（AVX-512） | v0.3.0（AVX2 だけ、`CELV2_SIMD=avx2`） |
|---|---|---|---|---|
| S1（アニメ 600 フレーム、6 場面） | CPU ms/フレーム | 2953 | 1737（−41%） | 1925（−35%） |
| S1 | fps | 10.5 | 12.2 | 11.5 |
| S2 AIR（アニメ 600 フレーム） | CPU ms/フレーム | 3338 | 2045（−39%） | 2267（−32%） |
| 吉村（実写） | CPU ms/フレーム | 4117 | 2656（−35%） | 3013（−27%） |

1080p、`--workers auto --refs 7 --qindex 130`、アニメは `--tune animation`、実写は `--tune film`。RTX 5090 と 24 コアの Xeon で、
ほかの処理のない状態で v0.2.0 と交互に 3 回ずつ符号化した中央値です。AVX2 の列は同じ CPU で AVX-512 の経路を切ったもので、
AVX-512 のない CPU での実測ではありません。

## 新しいこと（既定で有効）

圧縮：
- `--real-trellis`（既定 1）：量子化の格子探索を、実際に書く記号のビット数で行います（120 フレームで PSNR-Y −1.61%、CPU +2% 以内）。`--real-trellis 0` で以前の動きになります。`--psy-trellis` を 0 より大きくすると、`--real-trellis 1` を指定しない限り切れます。
- ループフィルタを 64x64 などの単位ごとに決めるようになりました：CDEF の強さ、CCSO のオンとオフ、輝度のループ復元（単位ごとの切り替えと画素クラスごとの Wiener）、色差のループ復元（64 / 128 / 256 の単位ごと）。
- RD の判定が、分割や参照などの横情報のビット数をフレームの確率表から見積もるようになりました（YUV −1.04%、Y −0.40%）。
- その見積もりで、8x4 / 4x8 のインターのブロックには書き手が実際に書く分だけを数えるようにしました（YUV −0.08%、Y −0.10%）。
- 参照フレームの入れ替え順（mini-GOP の中で、表示順で最も古いフレームの枠を使う）。
- 9 フレームより短い場面のキーフレームの qindex の下げ幅を、場面の長さに合わせて小さくしました。
- 画面の 1/4〜1/2 が止まったままの変化は、場面の切り替わりとして扱わず P フレームにします。
- skip mode の候補を、復号器が使う SHARP フィルタで評価するようにしました。

速さ（出力のバイトは変わらないもの）：
- RD の判定の計算を整数にし、メモ化とベクトル化をしました。ループフィルタの探索（CDEF、CCSO、ループ復元）も速くしました。
- 変換（fwd_dct）の 16 以上のサイズで、CPU に AVX-512 があれば使います。ない CPU では AVX2 の経路を使い、出力は同じです。
- Vulkan：動き探索をブロックごとのワークグループで（4K まで）、計算専用のキューを優先、GPU ごとに 1 つのデバイス。

その他：
- CUDA の経路をなくしました。GPU は Vulkan だけです（`--device cuda` はなくなりました）。v0.2.0 から Vulkan が既定です。
- GUI は変換に使うツールを「通常より低い」優先度で動かします（ほかのソフトが重くならないように）。詳細設定 > 速度・処理 > CPU の優先度 で切れます。celv2enc 単体では `--priority normal|below`（既定 normal）。

## 直したこと

- レターボックスやピラーボックス（上下・左右の黒帯）のある動画で、場面の切り替わりを見落としていました（2.39:1 で全部見落としていた）。黒帯は上下または左右の両側にあるときだけ黒帯として扱うので、片側の端だけが暗く平らな動画を黒帯と取り違えることはありません。
- `--psy-trellis` を 0 より大きくしても、`--real-trellis` が `--psy-trellis` の項を使わずに選び直すため、効果の大半が打ち消されていました。今は `--real-trellis 1` を指定しない限り、`--psy-trellis` が `--real-trellis` を切ります。
- インターのフレームの 8x4 / 4x8 のブロックで、書き手が書けないイントラの候補を RD の判定で比べていました（選ばれると、書くときに別のモードに置き換わっていた）。今はその候補を比べません。
- Vulkan の VRAM の見積もりが実際より 4% 少なく、空きの少ない GPU で共有メモリにあふれる配置を選ぶことがありました。
- Vulkan のデバイスが失われたときの後始末と、ホストが読む前の同期を直しました。
- celv2enc.exe が TensorFlow Lite をリンクしなくなりました（AVM の、CelV2 が使わない機械学習の部分を外してビルド）。ファイルが約 40% 小さくなり、出力は同じです。

## 確かめたこと

- テスト 37/37（`CELV2_SIMD=avx2` でも 37/37）。
- 8 素材 × 120 フレーム × 4 点を avmdec（AVM v1.0.0）と、upstream の dav2d main 9b5cef2（改造なし）で復号し、エンコーダの `--recon` とバイト単位で一致（32/32）。mini-GOP の設定を変えた S1 600 フレーム（B フレーム 0 / 7 / 15）も一致（3/3）。
- `CELV2_SIMD=avx2` と既定で S1 の出力が同じ（md5 が一致）。
- Intel Arc Pro B50 と RTX 5090 で、同じストリームと同じ `--recon` になる（1080p 33 フレーム、avmdec の出力とも一致）。

## 確かめていないこと・既知の制限

- **古い dav2d（2026 年 10 月まで、例：3812a7a）では再生できません。** 試した 8 本すべてで、異常終了するか、ほぼ全フレームが `--recon` と違いました。upstream main 9b5cef2 では 32 本とも一致しました。下の「dav2d で再生するには」を見てください。
- **AVX-512 のない CPU では動かしていません。** 変換の AVX-512 の経路は、CPU が AVX-512（F、BW、VL）に対応し OS が有効にしているときだけ使います。AVX2 の経路は `CELV2_SIMD=avx2` で強制して確かめました（テストと出力の一致）。AVX-512 のない CPU で正しく AVX2 を選ぶかどうかは、実機でしか確かめられません。
- レターボックスやピラーボックスのある動画では、「止まったままの部分」の割合に黒帯も数えます。また、場面の切り替わりを判定する差は、v0.2.0 と同じく黒帯を含む画面全体で測ります。このため黒帯の広い動画では、変化の小さい切り替わりを見落とすことがあります。v0.3 の後で直す予定です。
- SSIMULACRA2 では、アニメの一部（Dragon Maid、AM）と実写（crowd_run、park_joy）の AV1 との差が PSNR より大きく出ます。見た目の指標ではここが弱い所です。
- 低いビットレートほど AV1 との差が大きくなります。

## dav2d で再生するには

**なぜ古い dav2d で再生できないか**：dav2d は開発中のデコーダで、2026 年 10 月下旬までの版には、CelV2 が使う道具の復号に不具合や未対応の部分がありました。B フレームの動きベクトル（joint MVD、遠い参照との距離）、グローバルモーション、色差のループ復元（非分離 Wiener のフレームフィルタ）、10 ビットの低い q でのデブロッキング、セグメントごとの量子化、BAWP などです。このため、途中で異常終了する、フレームヘッダの解析に失敗する、絵がずれる、といったことが起きます。2026-11-12 の upstream main では、これらはすべて直っています。

**直すときの指針**
1. 正しく復号できているかの確認には、参照デコーダの AVM v1.0.0 の avmdec を使ってください：`avmdec --rawvideo -o avm.yuv 入力.ivf`
2. dav2d を使う場合は、upstream main の 9b5cef2（2026-11-12）以降を、改造なしでビルドしてください（meson、ninja、nasm が必要。Windows では Visual Studio の開発者プロンプトで実行）。
   ```
   git clone https://code.videolan.org/videolan/dav2d.git
   cd dav2d
   git checkout 9b5cef2
   meson setup build --buildtype=release --default-library=static
   ninja -C build
   ```
3. 照合：`build/tools/dav2d -q -i 入力.ivf -o dav2d.yuv --muxer yuv` を実行し、avmdec の出力とハッシュを比べます（`certutil -hashfile dav2d.yuv MD5`、または `md5sum`）。一致すれば正常です。9b5cef2 より新しい main で一致しないときは、9b5cef2 に戻してください。
4. Windows で `-o -`（標準出力）からパイプで渡すと、改行の変換で出力が壊れます（upstream では未修正）。ファイルに書き出すか、CelV2 のリポジトリの `docs/dav2d/dav2d-win-stdout.patch` を、ビルドの前に dav2d のフォルダで `git apply` してください（説明とライセンスは同じフォルダの README.md と COPYING）。
