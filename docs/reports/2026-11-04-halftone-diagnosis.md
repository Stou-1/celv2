# 網点の場面の診断（段階 1、2026-11-04）

設計書：docs/superpowers/specs/2026-11-04-halftone-analysis-design.md。Dragon Maid OP 120 フレーム 1080p。

## 結論

- **分岐 1（新しい絵が B フレームに落ちる）が当てはまる。** 新しい網点の絵が出る 4 フレーム（33、55、77、100）は、CelV2 ではすべて B フレーム：33・55・100 は参照されない B（qindex 146 = 130 + 16）、77 は中間の B（130）。x264 は 77・100 を I、55 を P、33 を B にした。
- **分岐 2（種類は合っているがビットが少ない）は当てはまらない。** CelV2 はこれらのフレームに x264 の 1.2〜1.9 倍のバイトを使い、それでも PSNR で 1〜2.5 dB、SSIMULACRA2 で 1〜17 低い。粗い qindex の B フレームで、新しい絵をほぼイントラで描いているため。
- **分岐 3（解析が網点を見落とす）は、設計書の兆候とは違う。** 新しい絵のフレームで mad は小さくない（33〜48）。切り替えにならないのは、ワイプが変化を数フレームに分けるため、直前 8 フレームの変化の中央値が大きく、「中央値の 4 倍」を超えないから。高周波の差 hf は網点の新しい絵で 15〜25、ほかで 3〜10 と、はっきり分かれる。
- **分岐 4 の兆候も一部ある。** 両方が B のフレーム 33 で、CelV2 は 1.2 倍のバイトで 0.9 dB 低い。同じ種類のフレームでも、網点の描き方そのもので負けている（`--screen` の IntraBC とパレットの根拠）。
- 段階 2 は分岐 1 から：大きな変化（ワイプの累計）でミニ GOP を切り、新しい絵のフレームをアンカー（参照、アンカーの qindex）にする。変化の判定に hf を使う（分岐 3 のセルの判定）。

## 条件

- CelV2：`--tune animation --refs 7 --qindex 130 --psnr --progress --recon`、`CELV2_GOP_LOG=1`（7a49395、`--paq 0.25` が既定）。
- x264：ffmpeg 9.0.2 の libx264、`-crf 26`、preset medium（既定）、他は既定。フレームごとの QP は x264 の統計ファイル（`pass=1`）から。
- PSNR-Y は 10 ビットで（x264 と元は 8 ビット ×4）。SSIMULACRA2 は libjxl v0.12.0、BT.709 の 16 ビット PNG。
- 合計バイト：CelV2 4,097,304、x264 3,386,022（全体の画質は近いが同じではない）。

## 新しい絵のフレーム（種類 / qindex・QP / バイト / PSNR-Y / SSIMULACRA2）

| フレーム | CelV2 | x264 |
|---|---|---|
| 33 | B / 146 / 109,919 / 36.01 / 52.5 | B / 31.3 / 89,716 / 36.95 / 64.9 |
| 55 | B / 146 / 162,121 / 33.99 / 47.9 | P / 31.3 / 141,136 / 35.55 / 53.0 |
| 77 | B / 130 / 178,615 / 39.65 / 67.5 | I / 28.4 / 139,949 / 38.67 / 68.5 |
| 100 | B / 146 / 190,321 / 34.32 / 51.1 | I / 28.3 / 164,269 / 36.77 / 68.0 |

- 77 は CelV2 の方が PSNR で上（中間の B で qindex 130）、SSIMULACRA2 はほぼ同じ。参照されない B に落ちた 3 つで差が大きい。
- 直後のフレームにも差が続く：34（CelV2 154,934 バイトで 35.55 dB、x264 80,160 バイトで 32.12 dB）、56、57、101。CelV2 は新しい絵を次のアンカーまで良い参照として持てず、後続の B にもビットを使っている。

- 33 の絵は、グループ 25（25〜32、アンカー 32）の直後、グループ 33（33〜40、アンカー 40）の先頭の B に落ちた。アンカーは 7 フレーム先の 40。
- グループ 25・49 は anchor_q が +10 / +15（TPL の r0 が 0.78 / 0.96：アンカーがほとんど参照されないと見た）。ワイプの途中のフレームがアンカーになり、新しい絵はその後ろの B。
