# `--paq`：知覚 AQ の計測（2026-11-04）

## 結論

- `--paq 0.25` が設計書の判定条件を満たした。8 素材の平均で SSIMULACRA2 −0.86%、XPSNR −0.91%（BD-rate、`--paq 0` に対して）、どの素材も +1% 以内（悪い方は 吉村 SSIMULACRA2 +0.61%、chika XPSNR +0.44%）。
- 0.5 / 1 / 1.5 は平均では良い（SSIMULACRA2 −1.5 / −1.6 / −0.8%、XPSNR −2.0 / −3.4 / −3.8%）が、AIR が +1.6〜+6.8%、吉村が +0.3〜+5.6% で条件に入らない。
- 実写の動きの多い素材に効く：park_joy −3.6 / −4.1%（0.25）、−12.9 / −14.4%（1）。crowd_run −0.4 / −1.8%（0.25）、−5.2 / −11.0%（1）。
- 時間は 1.03〜1.14 倍（マップの計算をスレッドで並列にした後。並列にする前は 1.1〜1.3 倍）。
- 既定値や `--tune` に入れるかは、見比べの後で決める（下の「見比べ」）。

## 設計書から変えたこと

- **絶対値の下限（コミット 072a034）**：粗くする側のオフセットを、log2(分散 + 1) が 4（分散 15）で 0、8（分散 255）で満額になるように絞る。psy-rd の設計書の「平ら」「忙しい」の境目と同じ値。AIR は空と雲だけの場面が多く、フレーム平均の log2(分散 + 1) が 2.0 しかない。そのため雲のなめらかなふちが「忙しい」と判定され、qindex が最大 +35 粗くされていた。0.5 での効果：AIR XPSNR +2.52 → +2.00%、VMAF +2.71 → +1.60%、AM −2.68 → −2.90%、park_joy −8.79 → −8.94%、吉村と crowd_run は ±0.05 以内。
- **テストの作り（6b066d1、1000b5d）**：計画の `sb64_leans_sensitive` は「忙しい中に平らな 16x16 が 1 つ」だったが、設計書の規則（25 パーセンタイルと平均の平均）は 16 個中 1 個では動かないので、「平らな中に忙しい列」にした。網点のテストは、P が粗くする側でしか計算されないので、下に平らな帯を足した。

`CELV2_AQ_STATS` の行で「超ブロックの中のばらつき > 超ブロック同士の差」のフレームの割合：AIR 1.00、chika 1.00、Dragon Maid 0.97、AM 0.83、Angel Beats 0.79、吉村・crowd_run・park_joy 0.00。アニメ 5 本では 128x128 の格子がマップの大部分を失っている。設計書の段階 B の条件（段階 A が残り、多くの素材で格子が失う）は、段階 A を既定や tune に入れると決まれば満たす。
